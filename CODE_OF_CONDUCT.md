# Code of Conduct

## Our Pledge

We as contributors and maintainers of this SIEM Detection Engineering Portfolio pledge to make participation in our project a harassment-free, professional, and collaborative experience for everyone.

We are committed to providing a welcoming environment focused on technical excellence, learning, and advancing detection engineering practices.

## Our Standards

### Positive Behavior

Examples of behavior that contributes to a positive environment:

- Using welcoming and inclusive language
- Being respectful of differing viewpoints and experiences
- Gracefully accepting constructive criticism
- Focusing on technical merit and objective analysis
- Providing detailed, helpful feedback on detection rules and code
- Sharing knowledge about SIEM platforms, threat detection, and MITRE ATT&CK
- Helping others learn detection engineering best practices
- Acknowledging and crediting contributions

### Unacceptable Behavior

Examples of unacceptable behavior:

- Personal attacks, insults, or derogatory comments
- Trolling, inflammatory comments, or intentional disruption
- Publishing others' private information without permission
- Spamming issues or pull requests
- Submitting malicious detection rules or code
- Harassment of any kind
- Other conduct which could reasonably be considered inappropriate

## Technical Standards

In addition to community standards, we maintain technical excellence:

### Detection Rule Contributions

- **Quality Over Quantity:** Submit well-tested, validated rules
- **Documentation Required:** All rules must include description, false positive analysis, and testing results
- **MITRE Mapping:** All rules must map to valid MITRE ATT&CK techniques
- **No Malicious Content:** Do not submit rules designed to hide malicious activity

### Code Contributions

- **Security First:** No code that introduces security vulnerabilities
- **Testing Required:** All Python scripts must be tested before submission
- **Follow Style Guidelines:** Adhere to PEP 8 for Python, YAML best practices for Sigma
- **No Plagiarism:** Only submit original work or properly attributed content

### Issue Reporting

- **Search First:** Check if the issue already exists before creating a new one
- **Provide Context:** Include rule ID, SIEM platform, log samples, and reproduction steps
- **Be Specific:** Vague reports like "rule doesn't work" are not actionable
- **False Positive Reports:** Use the template and provide legitimate triggering events

## Scope

This Code of Conduct applies to:

- GitHub repository (issues, pull requests, discussions)
- Communication about the project (emails, social media mentions)
- Community events or presentations featuring this portfolio

## Enforcement

### Reporting

If you experience or witness unacceptable behavior:

1. **Minor Issues:** Address directly with the individual if comfortable
2. **Serious Issues:** Report via email to [your.email@example.com]
3. **Immediate Threats:** Contact appropriate authorities

### Enforcement Actions

Project maintainers may take action including:

- **Warning:** Private or public warning about inappropriate behavior
- **Temporary Ban:** Temporary restriction from project interaction
- **Permanent Ban:** Permanent removal from the project community
- **Content Removal:** Deletion of comments, issues, or pull requests

Actions will be proportionate to the violation and consider context.

## Detection Engineering Community Values

This project specifically promotes:

### Technical Rigor
- Evidence-based detection engineering
- Peer review of detection logic
- Reproducible testing methodology
- Performance metrics and benchmarking

### Collaboration
- Sharing false positive tuning strategies
- Collaborative attack scenario development
- Cross-platform SIEM knowledge exchange
- Open discussion of detection limitations

### Learning
- Mentorship of junior detection engineers
- Documentation of lessons learned
- Sharing of testing methodologies
- Educational use of attack simulation

### Responsible Security
- Coordinated vulnerability disclosure
- No weaponization of detection bypasses
- Ethical testing practices
- Respect for production environments
